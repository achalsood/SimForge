## Application and package checks

The launcher resolves its default example exclusively from SDL_GetBasePath. Fonts, shaders and meshes are embedded. No runtime resource path points into the checkout. Explicit CLI paths retain normal working-directory semantics. Missing Vulkan is checked using the system loader before graphics initialization; a no-argument initialization exception produces an error dialog and console text. Missing SDL/MSVC imports are handled by Windows before main and documented with repair steps.

Recovery uses SDL_GetPrefPath (normally `%APPDATA%\SimForge\SimForge`); initialization failures are shown in the UI. Project saves/temporary replacements/backups and reports use user-selected locations. ImGui automatic INI/log writing is disabled. Screenshots require explicit diagnostic paths. Protected-install behavior is reviewed from these paths; an ACL-protected installation test and missing-system-runtime fault injection have not been performed.

Expected package root: `SimForge-v0.1.0-windows-x64/`, containing the two executables, SDL3.dll, build-info.json, package-inventory.json, README.txt, LICENSE/NOTICE/third-party notices, licenses/, assets/fonts/ notices, examples/ and docs/. Four curated inputs cover baseline, constrained resources, seeded Poisson demand and an embedded-source checkpoint request. Only the first three are scenario files.

The [packager](../../scripts/package-windows-release.ps1) checks clean Git/build/embedded identities, Release/runtime flags, imports, compiled shader/font inputs and required notices. Staging and extraction audits check exact inventory sizes/hashes, required files, relative paths, metadata, no extra files, no debug/build/credential artifacts, and outer ZIP SHA-256. ZIP entries use stable order and source-commit timestamps. No independent compiler bitwise-reproducibility claim is made. Dirty-source rejection was exercised before commit and created no output.

ZIP byte count, SHA-256 and the complete inventory are recorded in the generated release-receipt.json; checksum file: `SimForge-v0.1.0-SHA256.txt`. The generated github-release-body.md includes the literal checksum and exact commit link for approval/publication. The final artifact supplement records extraction, repeated packaging, negative audits and native runs after archiving. These post-commit values intentionally live outside the versioned ZIP/source contents.

## Native and independent extraction evidence

The [portable test runner](../../scripts/test-windows-portable.ps1) copies only the ZIP to a temporary directory with spaces and extracts it there. Normal startup uses a Windows-only PATH with SDK/vcpkg and Vulkan driver/layer override variables removed, from both the application's own directory and an unrelated directory. It records initialized-renderer/responsive-window startup time, working set, actual DLL paths and exit status, with a local Release comparison. Separate graphics diagnostics explicitly use the host's validation layers to exercise the launcher, baseline, constrained and Poisson scenarios, playback/camera/metrics, project Save/fresh-process Open and checkpoint interventions. Framebuffer captures, CPU frame means and console logs are retained. The runner checks that package resources remain byte-identical.

These native checks are pending the final committed package; their actual outcomes and measurements belong in the final artifact supplement, rather than being asserted in advance. Startup measures renderer initialization plus responsive-window discovery, not an instrumented first scanout. Frame means include FIFO/presentation synchronization and are not GPU execution time. Scenario commands verify completion and numerical outcomes; isolated scenario-parser latency is not measured. Automated desktop controls do not establish human usability or all shortcut/Explorer shell integrations.

No separate clean Windows machine/VM with compatible Vulkan graphics is available. WindowsSandbox.exe is absent on this host. Restricted-PATH extraction tests do not remove installed system runtimes, validation layers or drivers and are not clean-machine validation. No unsupported GPU/OS compatibility claim is made.
